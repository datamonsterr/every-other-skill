# every-other-skill

One repository for every skill we use, routed by [OtherSkill](https://github.com/datamonsterr/other-skill). Skills sit in a hidden, categorized bank; on each prompt OtherSkill asks a free OpenRouter model which categories and skills apply and injects only those. The bank covers the path from idea to shipped app: product discovery, product specs, frontend design, system architecture, tech stack, web and mobile, plus testing, skill authoring and agent workflow.

To find out whether a skill helps, [skill-up](https://github.com/alibaba/skill-up) runs the same task on the same project once per skill set, and [skill-ab-eval](https://github.com/cskwork/skill-ab-eval) judges the results blind against a rubric written before the runs.

## Layout

```text
every-other-skill/
├── otherskill.config.json     # categories + bankPath (.otherskill/bank); OtherSkill reads this
├── skillset.json              # what goes in the bank: source repo, skill path, categories
├── skills.lock.json           # generated: every skill with its upstream revision
├── .otherskill/bank/          # generated: <category>/<skill>--<id>/ full skill trees + licenses
│   ├── product/discovery/
│   ├── product/spec/
│   ├── design/frontend/
│   ├── architecture/
│   ├── techstack/  techstack/rust/
│   ├── web/
│   ├── mobile/
│   ├── testing/
│   ├── skills/
│   └── workflow/
├── skills/                    # skills authored here (test-skill)
├── scripts/
│   ├── sync.ts                # rebuild the bank from skillset.json
│   ├── list.ts                # print the bank by category
│   ├── install-global.ts      # make this bank the global OtherSkill bank
│   └── install-project.ts     # route one project to this bank
└── examples/<name>/           # one test project per skill set
    ├── project/               # starting files copied into every run
    └── evals/                 # skill-up suite: rubric.md, cases/, one <variant>.yaml per skill set
```

The bank is outside `.claude/skills` and `.agents/skills`, so no harness loads it natively. Each bank folder keeps the upstream tree, its license and an `.otherskill.json` with source URL and commit.

## Install

Prerequisites: [Bun](https://bun.sh) 1.3+, Git, and [OtherSkill](https://github.com/datamonsterr/other-skill):

```sh
curl -fsSL https://raw.githubusercontent.com/datamonsterr/other-skill/master/install.sh | bash
git clone https://github.com/datamonsterr/every-other-skill ~/dev/every-other-skill
cd ~/dev/every-other-skill && bun install
```

### Add the OpenRouter key

Routing uses one free OpenRouter model (`inception/mercury-decide:free`), so the key costs nothing. Create one at [openrouter.ai/keys](https://openrouter.ai/keys), then either export it:

```sh
echo 'export OPENROUTER_API_KEY=sk-or-v1-...' >> ~/.zshrc   # or ~/.bashrc
```

or save it privately (mode 0600 in `~/.config/otherskill/credentials.json`) without echoing it:

```sh
otherskill setup --non-interactive --scope global --agent claude --key-stdin
```

An exported `OPENROUTER_API_KEY` wins over the saved file. The key never goes into a config file or this repo.

### Make the skill set global

```sh
bun run install:global                       # Claude Code
bun run install:global -- --agents claude,codex --key-env OPENROUTER_API_KEY
bun run install:global -- --dry-run          # print the config it would write
```

This writes `~/.config/otherskill/otherskill.config.json` with `bankPath` pointing at this checkout and this repo's categories (your model, limits and harnesses are kept; the old file is backed up next to it), then runs `otherskill setup --scope global` to install the hook, launcher and `use-otherskill` companion. If you had a global bank before, the script prints its path; move skills you still want with `otherskill add <dir> --category <id> --scope project --cwd <this repo>`.

Check it, then restart your harness:

```sh
otherskill doctor          # bank, instances, hook, credential source
otherskill doctor --live   # one tiny free-model request
otherskill find --agent claude --prompt 'Design a landing page for a coffee roastery' --json
```

Because the global config points at this checkout, `git pull` updates the skills every repo sees. Repos with their own `otherskill.config.json` (superorchestrator, taphoa-mini) inherit this bank and these categories next to their own; set `"inheritGlobal": false` there to opt out.

### Use it in one project only

```sh
bun scripts/install-project.ts ~/dev/my-app                  # Claude Code
bun scripts/install-project.ts ~/dev/my-app --agents claude,codex
```

This writes `~/dev/my-app/otherskill.config.json` with an absolute `bankPath` to this checkout and these categories (an existing project config keeps its other settings), then runs `otherskill setup --scope project` in that project.

## Managing skills

`skillset.json` is the source of truth. To add a skill, find it, add an entry, sync:

```jsonc
{ "repo": "owner/repo", "label": "...", "skills": [{ "path": "skills/name", "categories": ["web"] }] }
```

```sh
bun run sync                      # full rebuild of .otherskill/bank (~1 min)
bun run sync -- --only expo       # only entries whose repo or path contains "expo"
bun run sync -- --dry-run         # print the plan
bun run list                      # bank by category; --category web, --json
```

Sync clones each repo once, copies every skill with `otherskill add`, rewrites provenance to the upstream GitHub URL and commit, copies licenses, and regenerates `skills.lock.json` and the table above. Review the diff and commit the bank. A new category goes in `otherskill.config.json` first.

Finding skills:

- `find-skills` (in the bank, category `skills`): `npx skills find <query>` searches [skills.sh](https://skills.sh).
- `otherskill search '<query>'`: GitHub `SKILL.md` search (needs `GH_TOKEN`).
- `skill-scout` checks local, marketplace and GitHub sources before you write a new skill.

Skills written here live in `skills/<name>/` and are listed in `skillset.json` with `"local": true`. Prefer an existing upstream skill; check its license (skip non-commercial ones).

## Testing skill sets

Each experiment is a [skill-up](https://github.com/alibaba/skill-up) suite in `examples/<name>/evals/`. `rubric.md` is written first: the question, the variants, the task, criteria scored 0–10 and pass/fail assertions. Then there is one skill-up config per variant (`baseline.yaml` with no skills, then one config per skill set) and a shared case. skill-up creates a fresh workspace for every run, installs only that variant's bank skills into `.claude/skills`, runs Claude Code headless with hooks disabled, applies the gates (files exist, build or typecheck passes) and keeps the workspace files. Judging happens afterwards in your Claude Code session with the [skill-ab-eval](https://github.com/cskwork/skill-ab-eval) skill: fresh judge subagents score anonymised outputs against the rubric.

Install skill-up (a single Go binary; Claude Code must be installed and logged in):

```sh
curl -fsSL https://raw.githubusercontent.com/alibaba/skill-up/main/install.sh | bash
```

Run every variant of one experiment without supervision:

```sh
ex=examples/landing-page
for f in $ex/evals/*.yaml; do
  skill-up run "$f" --model sonnet --iteration 2 --output-dir ".sandbox/$(basename $ex)/$(basename "$f" .yaml)" || true
done
```

Then ask Claude: *"Use test-skill to judge the landing-page experiment in .sandbox"*. The `test-skill` skill (bank categories `skills` and `testing`) covers the whole loop: rubric first, the suite, the unsupervised run, the blind judging with `skill-ab-eval`, and a keep/narrow/drop verdict in `examples/<name>/RESULTS.md`.

| Example | Question | Variants |
| --- | --- | --- |
| [product-discovery](examples/product-discovery/evals/rubric.md) | do PM skills sharpen problem framing and assumption tests? | baseline, pm-skills, product-lens, discovery-category |
| [landing-page](examples/landing-page/evals/rubric.md) | `frontend-design` with and without `design-taste-frontend` | baseline, frontend-design, taste, frontend-design+taste, design-category |
| [architecture](examples/architecture/evals/rubric.md) | Matt Pocock's design skills vs ECC's architecture skills | baseline, pocock, ecc, architecture-category |
| [techstack](examples/techstack/evals/rubric.md) | does research-first produce better justified stacks? | baseline, research-first, techstack-category |
| [web-app](examples/web-app/evals/rubric.md) | do React skills improve a Vite + React feature? (gate: build) | baseline, vercel, web-category |
| [mobile-app](examples/mobile-app/evals/rubric.md) | official Expo skills vs Callstack skills (gate: typecheck) | baseline, expo, callstack, mobile-category |

For full isolation (no user-level skills from `~/.claude/skills`), set `environment.type: docker` in the configs; see skill-up's [Writing Evals](https://alibaba.github.io/skill-up/guide/writing-evals) guide.

## Development

```sh
bun install
bun test          # bank integrity; every skill-up config resolves against the bank and has a rubric
bun run check     # biome format + lint, tsc
```

CI (`.github/workflows/ci.yml`) runs both on pushes to `main` and on pull requests.
